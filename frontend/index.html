How It Works

Two operations. Zero data on-chain. Complete auditability.

1. Your File

Any file: PDF, CSV, image, log — stays 100% on your machine.

2. SHA-256 Hash

Streamed in 64 KiB chunks. Produces a unique 32-byte fingerprint.

0x3a4b5c6d7e8f...

3. Sign & Broadcast

ECDSA secp256k1 signature. Sent to Sepolia via HTTPS RPC.

4. On-Chain Record

Immutable. Timestamped. bytes32 → ProofRecord in the contract.

Security

Security Model

Every threat considered. Every mitigation documented.

Raw data exposure

Only the hash is ever sent to the chain — never the data itself. Privacy-preserving by design.

Private key exposure

Loaded from .env file, never from CLI args or logs. Never appears in shell history.

Replay attacks

Wallet bound to chain ID. Transactions are chain-specific and cannot be replayed on other networks.

Duplicate storage

Contract reverts with DuplicateProof custom error — ~50 gas cheaper than require() + string.

Reentrancy

N/A — no ETH transfers, no external calls. State written before event emit (CEI pattern).

Hash collision

SHA-256 offers 2¹²⁸ collision resistance. Finding two files with the same hash is computationally infeasible.

What This Protocol Does NOT Provide
  • Confidentiality — the hash is public; anyone who has the file can verify it
  • Hash-to-file lookup — you need the original file to verify
  • Deletion — proofs are permanent once stored on the blockchain

Key Gas Optimization

The contract uses bytes32 (a fixed 32-byte slot) rather than string as the hash key, saving approximately 20,000 gas per store operation by avoiding dynamic storage allocation.

Applications

Real-World Use Cases

Any scenario where "prove this existed unchanged at this time" matters.
